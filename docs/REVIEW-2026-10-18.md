# 进度插件审查与修复记录

审查对象：`0.1.2-dsh021rc2.0`。方法：从使用目的推导验收标准，再独立构造会话状态和命令参数反例。

## 第一性原理

用户需要快速知道“正在做什么、走到哪里、是否需要自己处理”。进度卡表达本轮流程，不承担产物验收职责。因此，缺少计划回执不能阻止阶段推进；正常结束应自然收尾；真正的失败、中断、等待与断线仍须可见。动作优先于原始命令，文件名优先于长路径。

## 对抗式检查发现与处理

| 等级 | 可复现问题 | 修复 |
|---|---|---|
| P2 | 计划停在 pending/completed，真实工具运行中却没有当前执行阶段 | 工具活动可推进执行父阶段；正在规划的步骤保持原阶段 |
| P2 | 多条后续失败记录挤掉唯一仍在运行的动作 | 运行/等待优先于错误，再补最近活动 |
| P2 | 测试失败后重试成功，同名摘要仍永久红色 | 摘要采用最近的已结束结果；历史失败保留于详情 |
| P2 | “不删除/覆盖现有文件”等普通中文被误当路径 | 只缩短可辨识的文件引用，保留普通斜杠文本与否定约束 |
| P2 | printf/heredoc 写入漏识别，2>/dev/null 被标成“编写 null” | 识别首行输出文件，忽略空设备及文件描述符重定向，不读取 heredoc 正文 |
| P2 | grep/rg 的选项值导致搜索词混入文件列表 | 消费已知选项参数，文件目标与搜索文本分开 |
| P2 | 浏览器测试绑定个人用户名和本机绝对目录 | 使用模块解析、当前 home 与可配置环境变量，夹具使用合成路径 |

另修复文件名与通用关键词冲突：`Review src/progress.mjs` 保留 `progress.mjs`，不会被概括成“审查进度”。

## 验证结果

- 110 项单元测试全部通过，含本机宿主契约检查。
- 最终生成 bundle 的新鲜度检查通过。
- 22 项隔离浏览器检查通过，零页面运行错误；覆盖窄卡片、正常结束、失败、停止、断线、等待、历史重入、会话切换、详情导航与文件入口。
- 已在 macOS DSH 0.2.1-rc.2 安装并重启；真实历史会话显示“已答复”，四阶段自然收尾，命令变成简短动作，没有问号和“待核验”。
- 更新前完整备份安装依赖树与 profile 文件；更新后核对包内容、其他插件与设置未发生非预期变化。
